## Trigger
A matrix job on `windows-2025` with `-G "Visual Studio 17 2022" -A x64`, unchanged from a previously green configuration.
## What went wrong
The windows-2025 image now boots as `windows-2025-vs2026` (VS 2026 migration); no VS 2022 instance exists, so CMake configure fails with "could not find any instance of Visual Studio". The job log's "Image:" banner shows `windows-2025-vs2026`, which is the tell.
## Correction
Pin `runs-on: windows-2022` for the "Visual Studio 17 2022" generator (or adopt the VS 2026 generator name on windows-2025).
## Prevention rule
Treat runner image contents as perishable: when a Windows generator job breaks with "could not find any instance of Visual Studio", read the job's Image banner first, and pin the runner label that still carries the expected VS. If frozen tests assert runner labels, remember labels like `windows-2025` describe the pool, not the toolchain.
## Detection check
Windows configure step passes on the pinned image.
