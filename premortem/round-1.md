# Recursive pre-mortem — round 1

**Simulated incident:** six months after source release, users report that the instrument is unusable on one declared desktop platform, hosts crash on malformed sessions, CI had certified incomplete validation, and the supposed listening evidence was inaccessible or misleading—even though every plan step was followed.

## Incident reports

### PM-1 — Validator green without required coverage

- **Lens:** technical correctness, integrity, maintenance.
- **Root cause:** treating process exit status as proof of executed tests; stable pluginval race handled too broadly.
- **Severity:** Critical (verification reports success without running).
- **Mitigation:** D-005/D-011/D-014, S-080 exact options and log-family/completion/skip assertions; artifact post-conditions.

### PM-2 — Session/state input destabilises a host

- **Lens:** security, technical correctness, invalid assumptions.
- **Root cause:** XML/schema/parser abuse, state operations on audio thread, unbounded renderer resources.
- **Severity:** Critical.
- **Mitigation:** D-008/D-012/D-022/D-024/D-026, T-005/T-020/T-021/T-030/T-031 and S-090 hostile tests.

### PM-3 — One native target misses realtime performance

- **Lens:** scale/performance, CI coverage, operational maintenance.
- **Root cause:** Linux spike treated as cross-platform guarantee or baseline silently regenerated.
- **Severity:** High.
- **Mitigation:** D-018/D-029, native per-runner seven-run benchmark, absolute ceiling and stored bootstrap baseline; G-005 for a miss.

### PM-4 — Listening bundle cannot be delivered or overclaims evidence

- **Lens:** integrity, implementer misinterpretation, research assumptions.
- **Root cause:** branch-name mismatch, private repository access, reused reference sources treated as independent, numeric score substituted for slap judgement.
- **Severity:** High.
- **Mitigation:** D-028/D-030/D-071, T-050/T-051, S-000/S-100/S-LISTEN and G-004 qualitative override.

### PM-5 — Implementation drifts from the frozen environment

- **Lens:** dependency/supply-chain drift, past lessons, CI runner drift.
- **Root cause:** moving action tags, `-latest` runners, silent mirror/version/timeout changes or incomplete CMake staging.
- **Severity:** High.
- **Mitigation:** C-014–C-022/C-029, D-006/D-010, ENVIRONMENT exact pins, Rule 14 deviations and S-RETRO manifest diff.

### PM-6 — Model produces plausible bass but not psychobilly slap

- **Lens:** invalid research premise, technical correctness.
- **Root cause:** ordinary pizzicato references and bounded DSP proxies mistaken for perceptual slap realism.
- **Severity:** High.
- **Mitigation:** C-010 made non-load-bearing; D-071 limits references to ordinary pluck/body; ten demos expose slap and weak registers; G-004 requires human qualitative acceptance or rescope/stop.

### PM-7 — Credential or personal information leaks into public evidence

- **Lens:** security, operational reality, past lessons.
- **Root cause:** remote URLs, logs, local paths or listener metadata included in artifacts.
- **Severity:** Critical.
- **Mitigation:** D-026/D-030, T-051, repository/history and bundle scans; credential client only and no listener metadata.

## R0 lesson application check

All eight pre-existing planning lessons were checked: credential command lines → credential-client prohibition; cache socket mount → no reused planning credential; stale index lock → S-000 access check/halt; unreachable package mirror → D-010 public identical-pin fallback; CMake data/exec staging → ENVIRONMENT explicit rule; excessive spike lifetime → bounded S-040/S-090 workloads; generated bytecode staging → repository audit; fixture-before-stub red failure → D-027 adapter-first and frozen red verifier. No loaded lesson is inapplicable.

**Round result before hardening:** 3 Critical and 4 High incident classes. Their controls already present were checked for completeness; the newly discovered baseline, evidence-access, branch-pattern and pseudoreplication gaps required D-028–D-031 and are re-examined in round 2.
